# Winzo authoritative SQLite server

Firebase is removed from the authoritative game path. The Node.js server owns game state and SQLite persistence.

## Architecture

- `server.js` — authoritative game engine, WebSocket protocol, SQLite persistence, wallets, transactions, referrals, and bot scheduling.
- `index.html` — player Web App client. It never accesses SQLite directly.
- `admin.html` — admin transaction approval client.
- `.github/workflows/pages.yml` — deploys the static client/admin files to GitHub Pages.
- `.devcontainer/devcontainer.json` — Node 20 Codespaces environment and automatic server start.

## Codespaces test

1. Create the Codespace from this repository.
2. Make port `8080` Public.
3. Run `npm install` and `npm start` if the devcontainer did not start it automatically.
4. Test `https://YOUR-CODESPACE-8080.app.github.dev/health`.
5. In the GitHub Pages client, configure the WebSocket endpoint with the `server` query parameter, for example:
   `https://YOUR-PAGES-SITE/?server=wss://YOUR-CODESPACE-8080.app.github.dev`
6. The supplied client is intentionally in development mode for test-user authentication. A username entered on the login screen is sent as `devUsername` when Telegram `initData` is unavailable.

## Production / Telegram authentication

Set these environment variables on the authoritative server:

```text
NODE_ENV=production
PORT=8080
BOT_TOKEN=your_telegram_bot_token
ADMIN_KEY=your_private_admin_key
ALLOWED_ORIGIN=https://your-pages-site.example
SQLITE_DB_PATH=./winzo.sqlite
```

In production, Telegram `initData` is verified server-side. Do not rely on development username authentication. Do not leave `ALLOWED_ORIGIN=*` in production.

## Game behavior

- Two authoritative rooms: `room_15` and `room_30`.
- Maximum 3 picks per player per round.
- The server deducts the room bet for each successful pick and refunds valid unpicks/disconnections according to the round state.
- Bots use isolated internal IDs (`__bot_*`) while retaining human-readable display names, preventing bot/player username collisions.
- The server controls round timing, winner selection, payouts, persistence, and broadcasts.
- SQLite uses WAL mode and transactional wallet/transaction updates.

## Important deployment note

The ZIP cannot contain a real Codespaces URL because that URL is generated by GitHub for each Codespace. The client therefore keeps a configurable WebSocket endpoint instead of inventing one. The server must be running and publicly reachable before the player client can connect.

## Local checks

```bash
npm install
npm start
```

Then open `/health`. A successful response contains `ok: true`, `database: "sqlite"`, and the current state of both rooms.
